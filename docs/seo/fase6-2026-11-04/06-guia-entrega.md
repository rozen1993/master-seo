# Guía para diseñador, desarrollador y responsables

El paquete está preparado para trasladar requisitos a diseño y desarrollo. No contiene diseño elegido, código de web, configuración desplegable ni autorización de publicación. Empezar por README y trabajar siempre con el ID P01–P37 para no perder el vínculo con la auditoría.

| Responsable | Recibe | Devuelve para revisión |
|---|---|---|
| Dueño/operación | Insumos de cada ficha y decisiones condicionadas | Alcance, incluidos/opcionales, condiciones, disponibilidad, datos reales y expedientes de casos; aprobación por ficha |
| Editor/SEO | Fichas, matriz F5 y legado | Copy aprobado, mapa de equivalencia por sección, metadatos finales, selección de URLs y enlaces pertinentes |
| Diseñador | Arquitectura, bloques, jerarquía, CTAs y estados | Propuesta visual para elegir en encargo posterior; diseño completo responsive con errores, carga, envío y confirmación reales |
| Desarrollador | Rutas, indexación, schema, medición y aceptación | Implementación posterior con entorno, pruebas reproducibles, resultados y evidencia; nunca asumir host/hosting pendiente |
| Atención | Diccionario de medición y canales | Prueba correlacionada de recepción, reglas de cualificación y responsable del seguimiento |
| Revisor competente | Inventario de tratamiento real | Política y observaciones aplicables antes de activar esos flujos |
| Especialista Ads | Techo S/110 y discrepancias reportadas | Propuesta independiente basada en cuenta actual y gasto acumulado; sin ejecutar por aprobar estos documentos |

El diseñador puede trabajar estructuras con estados explícitos. Si se requieren ejemplos de maquetación posteriores, etiquetarlos como ficticios, mantenerlos fuera de producción y nunca simular permisos, RUC, razón social o dirección exacta. Ninguna ficha de este paquete incorpora datos de prueba. No presentar fotografías de stock como casos o equipo real.

El desarrollador usará los JSON como registros, no como código listo para producción. Debe resolver el host, proveedor de recepción y resto de variables antes de configurar. P36 es una plantilla, no un slug. P37 conserva capitalización y tipo PDF. No migrar fotografía por la mera disponibilidad de una landing. No enlazar destinos de tanda B hasta que existan y estén aprobados; un servicio confirmado puede describirse con salida a contacto verificado.

La entrega de cada página debe incluir ID/URL, versión de copy, evidencia de afirmaciones, permisos, assets y derechos, metadatos finales, enlaces activos, prueba de estado HTTP/indexación y aceptación aplicable. El paquete de lanzamiento añadirá las pruebas globales y la autorización concreta del dueño. El trabajo posterior debe conservar los originales históricos y referir expresamente este paquete como contrato vigente.

Preguntas comerciales agrupadas para el dueño: oferta y modalidades por servicio; ubicación/atención del estudio; capacidades/entregas y opcionales; rol y permiso de cada caso; datos y canales de atención; responsable legal del tratamiento; disponibilidad estacional. No hay que volver a confirmar que existen el estudio propio o los servicios sociales: falta concretarlos.

Las consultas externas pendientes ya están en cada ficha. Solo consultar de nuevo cuando una decisión dependa del dato; registrar fuente, consulta exacta, fecha, país/ciudad, idioma, dispositivo y costo. Volúmenes nacionales no equivalen a Lima; ausencia de filas o null no equivale a demanda cero. No repetir S024/S025/S036/S047 como si nunca se hubieran consultado.
